# Project brief

The north star. Everything else defers to this. Chung: correct anything below that
is wrong — it was written from a first conversation, not from your head.

## Who this is for

**Primary:** hiring managers and design leads recruiting for Product Design / UX
roles. They spend 2–5 minutes, on a laptop, often with tabs open to five other
portfolios. They are looking for evidence of judgment, not evidence of effort.

**Secondary:** peers and collaborators; future clients for independent work.

## What it has to do

1. Make the case that Chung thinks like a product designer, not only a maker of
   attractive artifacts.
2. Show range across disciplines *without* reading as unfocused.
3. Be memorable enough to survive a portfolio review of twenty candidates.
4. Load fast and work everywhere, because the alternative quietly costs interviews.

## Non-goals

- Not a blog. Not a CMS. Not a client project management system.
- Not a place to demonstrate every technique that exists. Restraint is the position.
- Not a JavaScript showcase — interactions serve the work, not the reverse.

## Success criteria

- [ ] Three case studies that a design lead would call "well argued"
- [ ] Loads in under 1.5s on a normal connection
- [ ] Lighthouse ≥95 performance / accessibility / best practices / SEO
- [ ] At least one interaction people mention unprompted
- [ ] Adding a new project takes under 30 minutes

## Constraints

- **Hosting:** GitHub Pages. Static only — no server, no database, no API keys.
- **Chung does not code.** Anything Chung must maintain has to be editable as text.
- **Custom domain:** planned, not bought. The site is pre-wired for it.

## The bet we're making with the stack

Astro ships zero JavaScript by default and adds React only where an interaction
lives. That means the site stays fast *as* it gets more playful, which is the exact
tradeoff most portfolios lose. If we'd picked an all-React stack, every cute idea
would tax every page.
